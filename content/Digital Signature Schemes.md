The Digital Signature Scheme is usually defined as $\Sigma = (\text{KGen}, \text{Sign}, \text{Ver})$
where,
  - $\text{KGen}$ is an algorithm which generates the key pairs ($sk$, $vk$) where $sk$ is Secret Key and $vk$ is Public Verification Key. It takes as input $1^{\lambda}$ , where $\lambda$ is the [[Security Parameter]]
  - $\text{Sign}$ is an algorithm that $(sk, I) \to \sigma$ (where $\sigma$ is the digital signature). 
  - $\text{Ver}$ (Verify) is an algorithm that takes the public parameters to verify if the sign is valid. $(sk, I, \sigma \to \{0,1\}$  $1 \to$ Valid ; $0 \to$Invalid/Tampered
# Secure Digital Signature Scheme

A digital signature scheme is secure if it satisfies two properties: correctness and strong unforgeability.
## Correctness
A digital signature scheme $\Sigma$ satisfies correctness if for every $\lambda \in \mathbb{N}$, and message $m \in \{0,1\}^*$, we have that:
  $$\Pr \left[ \mathsf{Vrfy}(\mathsf{vk}, m, \sigma) = 1 \;\middle|\; \begin{array}{c} (\mathsf{sk}, \mathsf{vk}) \leftarrow \mathsf{KGen}(1^\lambda), \\ \sigma \leftarrow \mathsf{Sign}(\mathsf{sk}, m) \end{array} \right] = 1 .$$
  
## Strong Unforgeability
A digital signature scheme $\Sigma$ satisfies strong unforgeability if for every $\mathsf{PPT}$ adversary $\mathcal{A}$, there exists a negligible function $\epsilon$ such that for all $\lambda \in \mathbb{N}$: $$\Pr[\mathsf{strongForge}_{\mathcal{A},\Sigma}(1^\lambda) = 1] \le \epsilon(\lambda) ,$$
where $\mathsf{strongForge}_{\mathcal{A},\Sigma}$ can be defined via a cryptographic game. 

**The $\mathsf{strongForge}_{\mathcal{A},\Sigma}(1^\lambda)$ Game:**
* The game begins by generating keys $(\mathsf{sk}, \mathsf{vk}) \leftarrow \mathsf{KGen}(1^\lambda)$ and initializing an empty set $Q := \emptyset$ to track queries.
* The adversary $\mathcal{A}$ is given the verification key $\mathsf{vk}$ and access to a *signing oracle $\mathcal{O}_s$*. The goal is to eventually outputs a candidate forgery $(m^*, \sigma^*)$.
* When $\mathcal{A}$ queries the oracle $\mathcal{O}_s(m)$, the oracle computes $\sigma \leftarrow \mathsf{Sign}(\mathsf{sk}, m)$, records the query by updating $Q := Q \cup \{(m, \sigma)\}$, and returns $\sigma$.
* The adversary wins if the output pair was never generated by the oracle ($((m^*, \sigma^*) \notin Q)$) AND the signature is valid ($\mathsf{Vrfy}(\mathsf{vk}, m^*, \sigma^*) = 1$).

### Intuition
"there are two definitions for the security of a digital signature scheme: existential unforgeability and strong unforgeability. The difference is that while in the "existential" condition is fulfiled only if the attacker cannot forge a signature on a message he did not ask the signature for. in the case of "strong" he even cannot generate another signature for a message he already ask for."
